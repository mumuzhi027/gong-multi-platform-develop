# 拱拱 PWA 部署与使用

当前前端部署方式：把 H5 静态文件交给 Nginx，通过同域 `/api/` 代理继续调用已有 Go 后端。前端服务器不需要运行 Node 或 Vue 开发服务。以下操作是部署说明，本次未连接或修改服务器。

## 需要准备

- 一个可使用的域名，例如 `gong.你的域名`，DNS A 记录指向前端服务器公网 IPv4。
- 如果有 AAAA 记录，也必须指向能正确提供这个网站的 IPv6 地址。
- 域名对应的有效 HTTPS 证书。Service Worker 在正式访问时需要 HTTPS；手机访问公网 HTTP IP 不具备完整 PWA 能力。
- 放通网站的 80、443 端口，以及前端服务器访问已有后端的网络连接。

使用独立子域名的根目录。当前 manifest、Service Worker、静态资源均使用 `/` 开头的路径，不要把构建结果放到 `https://域名/gong/` 等子目录。

## 1. 本地构建

在完整仓库内的 `uniapp3` 目录运行：

```powershell
npm ci
npm run build:h5
npm run test:assets
npm run test:pwa
```

已有 `node_modules` 时可以直接从 `npm run build:h5` 开始。资源同步脚本读取旁边的 `composeApp`，因此需要完整仓库；不要只复制 `uniapp3` 源码到一台机器上再构建。

保持默认同域配置即可：

```dotenv
VITE_H5_API_BASE_URL=/api
VITE_H5_WEB_BASE_URL=/web
VITE_BACKEND_PUBLIC_ORIGIN=http://101.43.27.78:8000
```

如需修改，写入 `uniapp3/.env.local` 后重新构建。变量写入编译后的前端；只在服务器上修改 `.env` 不会改变已经生成的网页。

要上传的是 `dist/build/h5` **里面的全部文件**：

```text
网站根目录/
  index.html
  sw.js
  manifest.webmanifest
  assets/
  static/
  pwa/
```

不要只上传 `index.html`，也不要把整个仓库、`src` 或 `node_modules` 作为网站目录。压缩包解压后确认 `index.html` 直接位于网站根目录，而不是多套了一层 `h5/`。

## 2A. 使用宝塔或其他 Nginx 管理面板

1. 为这个子域名创建一个静态网站。
2. 把构建文件上传并解压到该网站根目录。
3. 为网站申请有效证书、开启 HTTPS 和 HTTP 到 HTTPS 跳转。
4. 编辑该网站的 Nginx 配置，把 `nginx.locations.conf.example` 中的 `location` 配置放到现有 `server { ... }` 内。
5. 保留面板生成的域名、网站根目录和证书路径。已有同名 `location` 时先合并或替换，避免重复定义；该站点不需要 PHP 等动态语言处理。
6. 保存并检查 Nginx 配置，检查通过后重载。

这个片段特意使用 `^~ /api/` 等前缀，避免面板的通用图片、JS 缓存规则抢先处理后端海报或改变 PWA 更新策略。

## 2B. 已有 Linux + Nginx，使用 SSH 管理

这是独立站点配置说明。先上传静态文件到专用目录，例如 `/var/www/gong-pwa`，并确保 Nginx 用户可读取文件和进入父目录。

已有证书时，使用 `nginx.conf.example`，修改以下内容：

- 两处 `server_name`：改成实际子域名。
- `root`：改成实际网站目录。
- `ssl_certificate`、`ssl_certificate_key`：改成证书的实际绝对路径。
- 两处 `proxy_pass`：默认使用现有后端 `http://101.43.27.78:8000/`。如果同一服务器的后端监听在本机 8000，可以改为 `http://127.0.0.1:8000/`。

把站点配置放入系统实际加载的 Nginx 配置目录。很多 Linux 安装使用 `/etc/nginx/conf.d/`；已有网站不需要修改。

```bash
sudo nginx -t
sudo systemctl reload nginx
```

没有证书时，先为域名创建并启动 HTTP 静态站点，再通过面板或 Certbot 申请证书。取得证书后才启用引用证书文件的 HTTPS 配置；证书文件尚不存在时，Nginx 配置检查会失败。

Certbot 的安装和签发命令随发行版、安装方式而异，按官方步骤操作：https://certbot.eff.org/instructions 。

## 3. 后端代理为何必须配置

浏览器调用 `https://你的域名/api/login`，Nginx 转发至 `http://101.43.27.78:8000/login`。海报使用同一代理，条款网站使用 `/web/` 代理。

```nginx
location ^~ /api/ {
    proxy_pass http://101.43.27.78:8000/;
    proxy_set_header Host $proxy_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 60s;
    add_header Cache-Control "no-store" always;
}
```

这里 `proxy_pass` 末尾的 `/` 必须保留，才能按当前配置去掉 `/api/` 前缀。不能只上传网页而不配置代理，否则页面能打开，但登录和数据接口不能正常工作。

项目里的 `GONG_API_PROXY_TARGET`、Vite 代理和 `preview:pwa` 只用于本地开发或预览，生产部署使用 Nginx 配置。

## 4. 上线检查

电脑浏览器打开正式 HTTPS 地址并确认：

- 首页能打开；`/sw.js` 返回 JavaScript，`/manifest.webmanifest` 返回 JSON，而不是返回登录页 HTML。
- 使用真实账号登录后课程、成绩、空教室接口正常；活动海报和详情图能显示。
- 条款页面内容、访问路径正确。当前内置条款简版仍须核对为正式完整内容。
- 首次联网打开并等待资源缓存完成后，断网重开、切换课表等页面可用。断网能查看已缓存数据，不能重新登录或获取未加载过的最新数据、远程活动图片。

只进入“离线模式”可以测试界面，不能代替真实登录检查代理是否正确。

## 5. iPhone 使用

1. 用 Safari 打开正式 HTTPS 域名。
2. 打开分享菜单，选择“添加到主屏幕”。
3. 如果出现“作为 Web App 打开”，保持开启。
4. 以后从桌面的“拱拱”图标打开，使用独立窗口。直接在 Safari 标签页中访问仍会有浏览器工具栏。
5. 建议在添加后的桌面版里完成登录，再检查课程和图片显示。

## 6. 更新

代码修改后重新 `npm run build:h5`，上传最新的完整构建结果。发布时先上传 `assets/`、`static/`、`pwa/`，再上传 `index.html`、`manifest.webmanifest`，最后上传 `sw.js`。保留上一版带哈希文件名的 `assets`，不要在更新前先清空整个站点目录。

用户联网打开或回到应用时会检查新版本，下载完成后提示“立即更新”。也可以在设置中点“检查更新”。确认更新后应用重启，无需重新添加桌面图标。

如果使用 CDN，更新后刷新 `index.html`、`sw.js`、`manifest.webmanifest` 及 `static/`、`pwa/` 缓存；不要对整个网站启用无限期强制缓存。配置示例已为这些路径设置相应缓存头。

当前版本的后台课程/考试通知尚未接入。部署网站和添加桌面图标不会自动启用后台通知。
